## Findings considered and rejected

Recorded so they are not re-audited next run.

- **Cron does ~100 serial GitHub calls / cascading failure risk.** Reported by
  an audit pass, rejected: the `ctx.waitUntil` wrapper and the `LIMIT 50` caps
  bound it, and at current volume the batch is nowhere near full. The real
  defect in that loop is queue starvation, which plan 003 fixes. Revisit
  batching only if the backlog routinely approaches 50.
- **PR retry hits HTTP 422 after a partial failure.** Rejected as already
  handled: `commitFileOnNewBranch` force-updates an existing ref on 422
  (`src/lib/github-pr.ts:181-196`), and `markReport`/`markSubmission` only run
  after `proposeChange` resolves, so the "PR opened but D1 write failed" window
  does not leave an unretryable branch.
- **No per-IP rate limit on `/auth/magic`.** Rejected: Turnstile is the
  documented control for exactly this attack (the module header at
  `src/lib/turnstile.ts:1-16` records the 2026-07 bot campaign that motivated
  it), it fails closed on every error path, and the per-email cap in
  `src/lib/magic.ts` backs it up.
- **Turnstile fails open when `TURNSTILE_SECRET_KEY` is unset.** Rejected as a
  bug: it is deliberate and documented at `src/lib/turnstile.ts:13-15` so local
  dev and pre-secret deploys keep working. Plan 005 addresses the real problem —
  that the variable is invisible in `.env.example`, so a developer cannot tell
  the gate is off.
- **Apple `id_token` is not JWKS-verified** (`src/lib/apple-auth.ts:159-168`).
  Not rejected outright, but not planned: the token arrives server-to-server
  over TLS from Apple's own `/auth/token` endpoint, so this is defence-in-depth
  rather than an open door, and the code comment at lines 114-119 already states
  the tradeoff. Worth doing eventually (add signature + `iss`/`aud`/`exp`
  checks); worth recording in a decision log either way.

Added in run 2:

- **Split `sitemap.xml` into a sitemap index.** Not worth doing yet: 36,064
  URLs against Google's 50,000-URL / 50 MB per-file limit (14.5 MB), growing
  ≈3,350 URLs a year → ~4 years of headroom. Growth comes in jumps when a
  country is added, so a cheap build-time warning above 45,000 URLs is the
  sensible guard if anything.
- **Split the 2,143-line `src/routes/pages.tsx`.** No measured cost from size
  alone; a pure move would touch every import for no behaviour change. Do it
  only as part of extracting the triplicated panel query (below).
- **Malformed submission payload 500s the moderation page** (run-1 surfaced
  item). Downgraded to latent: `submissions.payload` is only ever written by
  `POST /add` with `JSON.stringify` (`src/routes/api.submissions.tsx:64-69`),
  and production has 0 submissions. Guard it only if another write path appears.
- **Make `users.email` UNIQUE** (identity ambiguity across auth paths). Not now:
  production has 0 duplicate emails, and the unique index would need a data
  check and migration coordination. Revisit if a duplicate ever appears.
- **Unhandled report kinds throw** (run-1 surfaced item). Downgraded to latent:
  every kind accepted by `POST /api/reports` has a handler; production reports
  use only closed / update_payment / update_tags / other / duplicate.
- **Expired-row sweep for `sessions`/`magic_links`.** Not rejected, folded
  forward: plan 012 removes the July backlog (most of the 650 expired links);
  a permanent hourly sweep in the cron is listed below as surfaced.
- **`/en/` trailing-slash 404.** Real, but low value: Hono's strict routing
  404s *every* trailing-slash URL, and nothing the site emits (links,
  hreflang, sitemap) uses one.

### Correction to plan 004's estimate

Plan 004 claimed ~10 MB saved, from a standalone Node prototype. Measured
properly against the executor's actual code — steady-state retained-heap floor,
same runtime, repeated to ±0.1 MB — the real figure is **23.8 MB → 16.3 MB, a
7.5 MB saving**. Still worth the change; the plan's number was optimistic.
Naive single-shot `heapUsed` sampling in Bun swings 11–43 MB and should not be
trusted for this kind of claim.
